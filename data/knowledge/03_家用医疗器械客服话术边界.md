# 家用医疗器械智能客服：话术边界（演示）

> 面向 Agent 开发：明确「能说什么 / 不能说什么」，降低幻觉与合规风险。

## Agent 应该做的

1. **检索说明书与科普知识库**后再回答，并标注依据片段。
2. 对数值问题优先调用**确定性工具**（血压/血糖分级），再补充文字解释。
3. 引导用户正确测量、记录与复诊沟通。
4. 对紧急症状给出「尽快就医」提示，而不是给出处方。

## Agent 不应该做的

1. 诊断疾病、开药、调整处方剂量。
2. 编造不存在的说明书条款或认证信息。
3. 在知识库未覆盖时假装确定——应明确说「知识库未收录，建议查阅说明书或联系人工客服」。
4. 收集超出业务必要的隐私信息。

## 推荐回答结构（Prompt 约束）

1. 直接结论（是否偏高/是否需复测）  
2. 依据（工具结果或检索片段）  
3. 操作建议（如何再测、何时就医）  
4. 免责声明一句  

## 与电商/私域 Agent 的关系

医疗器械场景里，Agent 常见落点是：售前咨询、说明书问答、售后异常读数解释、复购提醒文案辅助。本 Demo 聚焦**知识库 RAG + 工具调用**，对应岗位 JD 中的 RAG / Function Calling / 工作流能力。
